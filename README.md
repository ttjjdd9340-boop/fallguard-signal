# fallguard-signal

Fall Guard(라즈베리파이 + 파이썬)의 신호 처리 부분을 C로 다시 구현한 작은 프로젝트입니다. 센서 값을 최근 100개만 보관하는 링버퍼, 저역통과 필터, 충격 크기에 따른 알림 분기(Logic A/B)를 PC(Linux, WSL)에서 합성 데이터로 돌려봅니다.

## 만든 이유

파이썬 구현에는 두 가지 아쉬운 점이 있었습니다.

- 실시간 루프의 버퍼가 낙상이 감지될 때만 비워져서, 오래 켜두면 메모리가 계속 늘어납니다.
- 경미한 충격 뒤 15초 동안 버튼을 기다리는 동안 센서 읽기가 멈춥니다.

C로 옮기면서 첫 번째는 **고정 크기 링버퍼**로, 두 번째는 **기다리는 동안에도 샘플을 계속 받는 상태 머신**으로 바꿨습니다.

## 구성

| 파일 | 역할 |
|---|---|
| `sample.h` | 센서 한 번 읽은 값(가속도 3축, 자이로 3축) |
| `ring_buffer.c/.h` | 최근 100개(1초)만 보관하는 링버퍼 |
| `low_pass.c/.h` | 저역통과 필터 (alpha 0.3) |
| `detector.c/.h` | 필터 → 버퍼 → 후보 판정 → Logic A/B 상태 머신 |
| `main.c` | 가짜 센서 데이터를 만들어 넣고 결과를 출력 |
| `Makefile` | 빌드 |

## 빌드와 실행

```
make
./fallguard
```

## 실행 결과

```
[ 10.40s] 낙상 후보 (가속도 2.28g, 회전 98°/s) -> Logic B: 15초 취소 대기
[ 15.40s] 버튼 입력 -> 오탐으로 기록
[ 40.36s] 낙상 후보 (가속도 4.02g, 회전 287°/s) -> Logic A: 즉시 알림, 낙상 확정
[ 70.40s] 낙상 후보 (가속도 2.27g, 회전 97°/s) -> Logic B: 15초 취소 대기
[ 85.40s] 15초 동안 응답 없음 -> 낙상 확정
```

## 동작 방식

```
IDLE ──(최근 1초 최댓값 1.8g 이상)──▶ CAPTURING (충격이 지나가는 0.3초를 더 지켜봄)
                                          │
                  2.5g 또는 200°/s 이상 ──┴── 그 미만
                         │                         │
                  Logic A: 즉시 확정          WAITING (15초)
                         │                    │ 버튼 누름 → 오탐
                         │                    │ 시간 끝 → 확정
                         ▼                    ▼
                       COOLDOWN (3초 동안 다시 감지하지 않음) ──▶ IDLE
```

- 이벤트가 끝나면 버퍼와 필터를 비워서 같은 충격을 다시 판정하지 않습니다.
- 처음에는 후보를 발견한 즉시 판정했는데, 충격이 아직 올라가는 중이라 큰 충격도 경미한 충격으로 분류됐습니다. 그래서 0.3초 더 지켜본 뒤 판정하도록 바꿨습니다.

## 한계

- 합성 데이터(가짜 센서 값)로만 검증했습니다. 실제 센서나 MCU에서는 돌려보지 않았습니다.
- XGBoost 판정은 포함하지 않았고, 최근 1초의 가속도 최댓값이 1.8g를 넘으면 후보로 보는 임시 기준으로 대신했습니다. 1.8g와 0.3초는 직접 정한 값입니다.
- 처리 시간(샘플 1개당 약 0.3us)은 PC에서 잰 값이라 MCU 성능과 다릅니다.
